# Protocol: simmp v4

The wire protocol shared by the server and the Sims 4 client mod.

## Encoding

- TCP, text. Each frame is a JSON object, serialized as UTF-8.
- Framing: 4-byte big-endian unsigned integer length header, followed by
  exactly that many bytes of JSON.
- Maximum frame size: `1 MiB` (`MAX_FRAME_BYTES`). Bigger frames are rejected
  without being parsed.
- Every object has the same envelope:

```json
{
  "version": 4,
  "type": "HELLO",
  "request_id": "<uuid4 hex>",
  "payload": { ... }
}
```

- `request_id` is generated by `build_message()` and intended for
  request/response correlation in later milestones.
- Unknown types, unknown top-level keys, or a wrong `version` get an `ERROR`
  reply with `INCOMPATIBLE_VERSION` / `UNKNOWN_TYPE` codes and are dropped.

## Message catalogue

All payload fields are mandatory unless noted.

### Client -> Server

| Type | Payload | Notes |
|------|---------|-------|
| `HELLO` | `client_name`, `client_version`, `protocol_version` | First message a client sends. Server replies `WELCOME` + `ROOM_STATE` and places the player in the `lobby` room. |
| `PING` | `client_time` (float) | Heartbeat. Server replies `PONG`. |
| `JOIN_ROOM` | `room_id` | Join/switch to a room. Server replies `ROOM_STATE` for the target room and broadcasts `PLAYER_LEFT`/`PLAYER_JOINED` in the affected rooms. Unregistered clients get `ERROR NOT_REGISTERED`. |
| `EVENT` | `event_type`, `data` (any JSON), `seq` (int) | Replicated event. `seq` is the sender's sequence number; the server acks it (`EVENT_ACK`) and broadcasts it to the other members of the sender's room. `data` is relayed verbatim. Resent events (same `seq`) are acked again but not re-broadcast. |
| `PRESENCE` | `zone_id` (int), `lot_id` (int), `timestamp` (float) | Lightweight presence heartbeat: your current zone/lot. The server stamps `player_id` + `room_id` and relays it inside the room (not echoed to the sender). No ack. |
| `TRAVEL_REQUEST` | `zone_id` (int) | Initiate a group travel to `zone_id` for the whole room. Optional `player_id` (int) is accepted but unused. The room's other members each get a `TRAVEL_INVITE`. |
| `TRAVEL_RESPONSE` | `accepted` (bool) | Reply to a `TRAVEL_INVITE`. Optional `reason` (str) is attached to the `TRAVEL_ABORT` when rejecting. |
| `TRAVEL_READY` | `zone_id` (int) | Report that you arrived at the travel target. Sent after `TRAVEL_BEGIN`; can be triggered automatically by the game hook or manually. |
| `CLOCK_SYNC` | `zone_id` (int), `absolute_ticks` (int), `real_time` (float), `clock_speed` (int) | A reference sample of the game clock. The server stamps `player_id` and relays it to the room (not echoed to the sender), so peers can compute a clock offset. Used after travel completes by the initiator's stored beacon; also accepted at any time manually (e.g. `mp.clock`). |
| `OBJECT_CLAIM` | `key` (str) | Request authority over `key` in your current room. On success the server replies `OBJECT_CLAIM_ACK` to you and broadcasts `OBJECT_OWNERSHIP` to the room; on failure it replies `ERROR OBJECT_LOCKED`. |
| `OBJECT_RELEASE` | `key` (str) | Give up authority over `key`. The server always acks (`OBJECT_CLAIM_ACK`), and broadcasts `OBJECT_OWNERSHIP` (owner `null`) if you held the object. |
| `OBJECT_UPDATE` | `objects` (`[{"key": str, "rev": int, "fields": {...}}]`) | Report changed fields of objects you claim. `rev` is the sender's local revision counter (validated, not yet used for conflict resolution). The server verifies ownership, applies only the changed fields, and relays `WORLD_DELTA` to the room. Errors: `OBJECT_NOT_FOUND` (first reference to an unclaimed key), `OBJECT_LOCKED` (owned by someone else). |
| `INTERACTION_REQUEST` | `object_key` (str), `interaction` (str) | Propose starting an interaction (`interaction` is e.g. a trait/context name; the canonical list is an open research item) on `key` in your current room. Optional `args` (dict of JSON primitives). First come, first served per object: you either trigger a broadcast `INTERACTION_START` to the whole room (including you) or get an `ERROR` (`INTERACTION_BUSY`, `INTERACTION_COOLDOWN`). |
| `INTERACTION_END` | `object_key` (str) | Declare the interaction on `key` finished. On success the room gets `INTERACTION_FREE` (including you); if you are not the holder you get an `ERROR INTERACTION_NOT_HELD`. |
| `TIME_READY` | `zone_id` (int) | Report that your game has loaded `zone_id` and is ready to play. The server holds the room's clock PAUSED until **every** participant (members + disconnected ghosts) has signalled ready. Sent automatically on connection when the zone is already running and again after each `WELCOME`. |
| `TIME_SPEED` | `speed` (int) | Request a room clock speed: 0 = paused, 1 = normal, 2 = fast, 3 = fastest. Optional `ticks` (int) is a game-clock timestamp to go with the change. The server stores the desire (last change wins) and broadcasts `TIME_SYNC`; while the gate is closed the broadcast remains PAUSED until every participant readies. |

Server-stamped fields (`EVENT.player_id`, `PRESENCE.player_id`, `PRESENCE.room_id`, `CLOCK_SYNC.player_id`, `TIME_SYNC.player_id`, `WORLD_DELTA.player_id`, `OBJECT_OWNERSHIP.player_id`, `INTERACTION_START.player_id`) are optional on the wire and may be omitted by senders.

### Server -> Client

| Type | Payload | Notes |
|------|---------|-------|
| `WELCOME` | `player_id` (int), `protocol_version`, `server_time` (float), `room_id` | Assigned identity + current authoritative room + server clock. |
| `ROOM_STATE` | `room_id`, `players` (`[{"player_id": int, "name": str, "connected": bool}]`) | Authoritative roster snapshot for the room the client is in. |
| `PONG` | `client_time`, `server_time` | Echo of the client's stamp plus server time; can be used for offset + ping estimation. |
| `PLAYER_JOINED` | `player_id`, `name`, `room_id` | Broadcast to a room's other members when someone joins. |
| `PLAYER_LEFT` | `player_id`, `room_id`, `reason` | Broadcast to a room's remaining members; `reason` is e.g. `"disconnected"` or `"switched_room"`. |
| `EVENT_ACK` | `seq`, `room_id` | Sent to the **sender** of an `EVENT` once the server accepted it. On a later `EVENT` with the same `seq` (a resend) the server acks again (so the client can drop it from its pending buffer) but does not re-broadcast. |
| `TRAVEL_INVITE` | `zone_id`, `requester_id` (int), `requester_name` (str) | Sent to every room member except the initiator, carrying the shared `request_id`. Reply with `TRAVEL_RESPONSE`. |
| `TRAVEL_BEGIN` | `zone_id` | Broadcast to the whole room once **every** invitee has accepted (or immediately when the initiator is alone). Every member should travel to `zone_id` and later report `TRAVEL_READY`. |
| `TRAVEL_COMPLETE` | `zone_id` | Broadcast when every member reported `TRAVEL_READY` for the target zone. If the initiator had a stored `CLOCK_SYNC` beacon, it is relayed right after complete so the room can realign its clocks. |
| `TRAVEL_ABORT` | `reason` (str) | Broadcast when the travel cannot proceed: someone **declined** (`"declined by <name> (<reason>)"`), a member **disconnected**, a deadline passed (`"invite timeout"`, `"ready timeout"`), a member reported **ready in the wrong zone**, or a newer request **superseded** it. |
| `ERROR` | `code`, `message` | Reply to a bad message. See codes below. |
| `WORLD_STATE` | `room_id`, `objects` (`[{"key": str, "owner": int\|null, "fields": {...}}]`) | Full snapshot of the room's object catalog. Sent right after `WELCOME`/`ROOM_STATE` on `HELLO` and right after `ROOM_STATE` on `JOIN_ROOM`. Replaces the client's mirror wholesale. |
| `OBJECT_OWNERSHIP` | `room_id`, `key`, `owner` (int\|null) | Broadcast to a room when `key` changes hands. `owner` `null` means released. Not echoed to the sender (`player_id` identifies the origin). |
| `OBJECT_CLAIM_ACK` | `key`, `owner` (int\|null) | Sent to the requester of `OBJECT_CLAIM`/`OBJECT_RELEASE`. `owner` is your `player_id` after a claim, `null` after a release. |
| `WORLD_DELTA` | `room_id`, `seq` (int), `updates` (`[{"key": str, "fields": {...}}]`), `player_id` (int) | Incremental world update relayed to the room (excluding the sender). `seq` is a per-room monotonic number assigned by the server; only actually-changed fields are included. Clients discard deltas with `seq <= last seen` or from another room. |
| `INTERACTION_START` | `room_id`, `object_key`, `player_id` (int), `interaction` (str), `started_at` (float) | Broadcast to the **whole room including the sender** when an interaction starts (echo-style, so one broadcast self-heals every mirror and no separate ack is needed). Optional `args` (dict of JSON primitives). `started_at` is the server's monotonic clock at grant time. |
| `INTERACTION_FREE` | `room_id`, `object_key`, `cooldown_until` (float) | Broadcast to the **whole room including the sender** when an interaction is released: explicit `INTERACTION_END`, watchdog expiry, or ghost eviction. `cooldown_until` is a server-clock timestamp; the object is blocked for interaction until then. |
| `INTERACTION_STATE` | `room_id`, `interactions` (`[{"object_key": str, "player_id": int, "interaction": str, "started_at": float, optional "args": {...}}]`) | Snapshot of every active interaction in the room. Sent right after `WORLD_STATE` on `HELLO` and after `ROOM_STATE`/`WORLD_STATE` on `JOIN_ROOM`, so a client that missed broadcasts self-heals. |
| `TIME_SYNC` | `speed` (int), optional `ticks` (int), optional `player_id` (int) | Authoritative room clock broadcast to every member (including the sender). `speed` is the effective speed: `0` while the gate is closed (any participant not ready, or mid-session disconnect), otherwise the last requested speed. `player_id` is who last requested a speed change (`null` when default). Clients must enforce `speed` locally and use the echo window to avoid re-sending their own change. |

### Travel handshake

One `TravelSession` is active per room at a time; a new `TRAVEL_REQUEST`
supersedes (aborts) the previous one. State machine:

```
            all accepted (or solo)
PENDING  --------------------------->  TRAVELING  --all members READY-->  COMPLETE
  |                                      |   |                                  |
  | decline / disconnect / invite-time   |   +-- READY for wrong zone ---------> ABORTED
  +------------------------------------->+  +-- ready-timeout / disconnect ----> ABORTED
```

- Members are frozen when the request starts (whoever is connected in the
  initiator's room at that moment). A player who joins mid-travel is not
  waited on but still sees the outcome broadcasts.
- The coordinator runs watchdog timers (invite: 15s, ready: 30s by default;
  injectable at construction for tests) and cancels the session on member
  disconnect. Abort broadcasts and cleanup are idempotent.

## World replication

A small per-room object catalog lives authoritatively on the server. Clients
**do not** push the whole world - they reserve (claim) the objects they want
to interact with and then send only the fields that changed.

Ownership model (server-authoritative):

- `OBJECT_CLAIM` is "first come, first served" per `key` inside the room.
  The server replies `OBJECT_CLAIM_ACK` (with the new owner) and broadcasts
  `OBJECT_OWNERSHIP` to the room so every mirror reflects the change.
- `OBJECT_UPDATE` on a `key` the sender does not own is rejected
  (`OBJECT_LOCKED`); `OBJECT_UPDATE` introducing a brand-new key that was
  never claimed is rejected (`OBJECT_NOT_FOUND`).
- `OBJECT_RELEASE` clears the owner; `OBJECT_CLAIM_ACK` still confirms it, and
  `OBJECT_OWNERSHIP` (owner `null`) is broadcast so mirrors drop the owner.
- Ownership is per-room and dies with the connection (the catalog entry itself
  survives so a later arrival can claim the same key).

Delta flow:

- The server merges each accepted `OBJECT_UPDATE` into the catalog entry,
  keeping only fields that actually changed, bumps a per-room `seq`, and
  relays `WORLD_DELTA` to the other room members.
- New arrivals get the full catalog via `WORLD_STATE` (sent directly after
  `ROOM_STATE` on both `HELLO` and `JOIN_ROOM`), so a missed delta self-heals
  on room join.
- The client keeps a `WorldMirror` of its room: `apply_full` replaces it,
  `apply_delta` merges fields (dropping stale `seq`s), and per-object
  `display_position(now)` eases between snapshots for smoothing. Which
  objects a client pushes is decided by a pluggable **sampler**
  (`set_world_sampler`); only objects the local mirror owns are sent.

`fields` values must be JSON primitives (`null`/bool/int/float/str). Keys and
field names are capped (see Limits); `WORLD_DELTA.seq` starts at 1.

## Interaction sync

A per-room interaction table lives authoritatively on the server. It answers
one question: **who is currently using object `key`?** Semantics:

- `INTERACTION_REQUEST` is granted **first come, first served** per `key`
  inside the room. The server records the holder, stamps `started_at`, and
  broadcasts `INTERACTION_START` to the whole room (echo-style). A request for
  a busy key gets `INTERACTION_BUSY`; a key inside a cooldown window gets
  `INTERACTION_COOLDOWN`.
- `INTERACTION_END` releases the object and starts `interaction_cooldown`
  (default 5s): the room gets `INTERACTION_FREE` with `cooldown_until`, and
  during the window new requests for that key fail with `INTERACTION_COOLDOWN`.
- A watchdog auto-releases any interaction older than `interaction_max_duration`
  (default 300s) — locked-sim protection if a client dies without sending END.
  It runs in the same reaper sweep as keep-alive/presence (a released
  interaction emits the same `INTERACTION_FREE` broadcast).
- A disconnected holder does **not** release their interactions immediately.
  The player becomes a **ghost** (see Ghost ownership below): world ownership
  and held interactions stay reserved for `ghost_ownership_ttl` (default 60s),
  and only when the ghost is evicted does the room get the corresponding
  `INTERACTION_FREE` / `OBJECT_OWNERSHIP` (owner `null`) broadcasts.
- The **sender receives every broadcast too** (unlike world/presence/event
  routing), by design: one server broadcast both confirms the grant locally
  and updates the rest of the room, so there is no separate ack message and a
  lost broadcast self-heals on room join via `INTERACTION_STATE`.

On the client side a `InteractionMirror` tracks `(object_key ->
player_id/interaction/started_at/args)` plus surface-level `cooldown_until`
bookkeeping. Which interactions a client proposes is decided by a pluggable
**sampler** (`set_interaction_sampler`); the periodic sync tick proposes keys
the sampler reports and ends interactions the sampler no longer reports,
skipping keys the mirror says someone else owns or that are denied. Denial
backoff: a key rejected with `INTERACTION_BUSY`/`INTERACTION_COOLDOWN` is not
retried for 10s (or until a `INTERACTION_START`/`INTERACTION_FREE` clears it).

`args` values must be JSON primitives. The `interaction` type string is capped
(see Limits); the canonical interaction vocabulary is an open research item
(see `docs/sims4-research.md`).

## Reliability (lightweight "reliable-room" layer)

- Every `EVENT` carries a monotonically increasing `seq` chosen by its sender
  (starts at 1).
- The server acks each accepted event back to the sender (`EVENT_ACK`),
  which removes it from the sender's pending buffer.
- The sender keeps un-acked events in a bounded pending buffer (default 64;
  oldest evicted on overflow).
- On reconnect the engine re-runs `HELLO` and **re-sends every pending
  event**. The server dedupes by `seq`.

### Stable identity across reconnects (`HELLO.client_id`)

`HELLO` takes an optional `client_id` (string, <= 64 chars). The server keeps
the identity mapping after a disconnect, so a returning `client_id`:

- reuses the **same `player_id`** and the **same room**,
- keeps its `last_event_seq`, so resends of already-relayed events are
  deduped across sessions (no duplicate delivery to peers),
- keeps presence/roster continuity (subscribers see `PLAYER_LEFT` on
  disconnect and `PLAYER_JOINED` on resume).

If a second connection says the same `client_id` while the old one is still
open, the server closes the stale connection and adopts the identity
("takeover"), so reconnect races cannot end up as two players.

### Ghost ownership (world + interactions survive a disconnect)

A disconnect does not immediately release what the player held. Registered
players track a `disconnected_at` stamp and become "ghosts" until the TTL:

- **Reserved during the ghost window.** The player's owned objects and held
  interactions stay in place and no release broadcast is emitted. A reconnect
  with the same `client_id` during the window is a **takeover/resume**: same
  `player_id`, same room, and the reconnect snapshots (`WORLD_STATE` +
  `INTERACTION_STATE`) already show the reserved ownership, so no state is
  lost. A `HELLO` resume also clears `disconnected_at`.
- **Evicted after `ghost_ownership_ttl`.** The reaper releases every interaction
  the ghost held (cooldown + `INTERACTION_FREE`), clears ownership on every
  object the ghost owned (`OBJECT_OWNERSHIP` owner `null`, excluding the dead
  peer), and drops the identity from `_players`/`_by_client_id`. A much-later
  reconnect then starts fresh with a new `player_id`.
- **Client-side fallback.** On a drop the client captures what it owned/held
  (`_capture_dropped_state`) and, after the reconnect snapshots arrive, re-claims
  world keys that are not owned by anyone else and re-proposes interactions that
  are unheld, not denied, and past cooldown. This covers the case where the
  server's own state was lost (e.g. a server restart) while the ghost's resume
  path covers the normal case.

## Connection lifecycle: keep-alive and stale reaping

The server treats **any** successfully parsed frame as connection activity.
A background sweep every `reap_interval` (default 5s) closes connections that
were silent for longer than `stale_timeout` (default 15s):

- Clients keep their connection alive by sending `PING` heartbeats on a timer,
  so an active client is never reaped.
- A reaped (or TCP-broken) connection surfaces as a reader EOF, which runs the
  same disconnect path as a clean close: `PLAYER_LEFT` (reason
  `"disconnected"`) to the room, presence cleared, and any in-flight travel is
  aborted. A `HELLO` that takes longer than `stale_timeout` is treated as a
  disconnect too (unwelcomed connections are reaped the same way).
- There is intentionally **no** `ERROR` for a stale connection: silence is
  healed by the disconnect broadcast, not an error reply.

Server-cached `PRESENCE` is also time-bound. The server tags each presence
with a local arrival time and, in the same sweep, drops cached snapshots older
than `presence_ttl` (default 30s). Each client mirror independently purges its
own `PRESENCE` copies with the same `presence_ttl`, using its **local** arrival
time (peer timestamps are not used because clocks are not synchronized). The
purge is local bookkeeping only — no extra messages are exchanged.

## Room broadcast routing

The server keeps one authoritative roster per room (`Session`). On
`JOIN_ROOM`, `PLAYER_JOINED`, and `PLAYER_LEFT`, the server re-sends the full
`ROOM_STATE` to every member of the room involved, which keeps the clients'
mirrors self-healing even if a broadcast is lost. `EVENT`/`PRESENCE` are
relayed with the server-stamped origin identity and are room-scoped (never
echoed back to the sender).

## Error codes

- `MALFORMED` - bad structure, wrong field types, unknown fields, over-long
  strings, or frame too big.
- `UNKNOWN_TYPE` - an unknown `type` string.
- `INCOMPATIBLE_VERSION` - `version` (envelope) or `protocol_version`
  (HELLO payload) mismatch.
- `ALREADY_REGISTERED` - protocol violation, e.g. a second `HELLO`.
- `NOT_REGISTERED` - the client sent a message (other than `HELLO`) before it
  was welcomed.
- `OBJECT_LOCKED` - `OBJECT_CLAIM`/`OBJECT_UPDATE` for a key already owned by
  another member of your room.
- `OBJECT_NOT_FOUND` - `OBJECT_UPDATE` first references a key that was never
  claimed (nothing is created implicitly).
- `INTERACTION_BUSY` - `INTERACTION_REQUEST` for a key another room member is
  already using.
- `INTERACTION_COOLDOWN` - `INTERACTION_REQUEST` for a key inside the release
  cooldown window.
- `INTERACTION_NOT_HELD` - `INTERACTION_END` for a key you do not currently
  hold.

## Limits

From `protocol/simmp/constants.py`:

- protocol version **4**
- `MAX_FRAME_BYTES` = 1 MiB
- `MAX_STRING_LENGTH` = 512 (client_version, code, message, reason)
- `MAX_NAME_LENGTH` = 64 (client_name, player name, requester_name)
- `MAX_ROOM_ID_LENGTH` = 64
- `MAX_EVENT_TYPE_LENGTH` = 128
- `MAX_CLIENT_ID_LENGTH` = 64
- `MAX_INTERACTION_TYPE_LENGTH` = 128 (interaction type strings)
- `MAX_OBJECT_KEY_LENGTH` = 64 (object keys and field names)
- `MAX_OBJECT_FIELDS` = 32 (fields per object)
- `MAX_OBJECT_UPDATE_OBJECTS` = 16 (objects per `OBJECT_UPDATE`; `WORLD_STATE`/
  `WORLD_DELTA` have no object-count cap)
- `MAX_OBJECT_VALUE_STRING` = 256 (string field values)

## Builders

Use `protocol/simmp/messages.py` to construct messages; builders validate
eagerly, so a bug in the caller cannot put a malformed message on the wire:

```python
from simmp import messages as msg

msg.make_hello("my-game", "0.1.0")
msg.make_event("sim.landed_on", {"lot": 12}, seq=7)
msg.make_event_ack(7, "lobby")
msg.make_presence(24, 3)
msg.make_travel_request(4242)
msg.make_travel_response(True, request_id_value="<id from the invite>")
msg.make_travel_ready(4242, request_id_value="<same id>")
msg.make_clock_sync(4242, 100000, 2998527000.0, 1)
msg.make_object_claim("sofa")
msg.make_object_release("sofa")
msg.make_object_update([{"key": "sofa", "fields": {"x": 1.0, "y": 2.0, "z": 3.0}, "rev": 4}])
msg.make_interaction_request("sofa", "Read", args={"book": "Tome"})
msg.make_interaction_end("sofa")
msg.make_interaction_start("lobby", "sofa", "Read", 1000, 123.5)
msg.make_interaction_free("lobby", "sofa", 128.5)
msg.make_interaction_state("lobby", [{"object_key": "sofa", "player_id": 1000, "interaction": "Read", "started_at": 123.5}])
msg.make_error("ROOM_FULL", "room is full", ref="sofa")
```

Serialization lives in `protocol/simmp/framing.py`:

```python
frame = framing.encode(message)      # -> bytes (length header + JSON)
parsed = framing.decode(frame_bytes) # -> dict (raises on bad framing)
```
